# CLAUDE.md -- fMRIPrep-rodents

## Project overview

fMRIPrep-rodents (`fprodents`) is a NiPreps BIDS-App that adapts fMRIPrep's
functional MRI preprocessing pipeline for rodent (currently rat) imaging.
The Python package name is `fprodents`, installed as `fmriprep-rodents`.
The CLI entry point is `fprodents`.

At present only rats are fully supported. The Fischer344 rat brain template
(from TemplateFlow) is the default standard space. Mouse support is planned
but not yet implemented -- it requires a suitable mouse template in TemplateFlow.

The project is maintained by the NiPreps community under
<https://github.com/nipreps/fmriprep-rodents>.

## Architecture

### Relationship to fMRIPrep

This is NOT a fork that tracks fMRIPrep's git history. It is a standalone
package that DEPENDS on fMRIPrep's ecosystem libraries:

- **niworkflows** (>=1.5.2) -- reusable NiPreps workflow building blocks
- **smriprep** (>=0.11.1) -- anatomical preprocessing (template construction, etc.)
- **nirodents** (>=0.2.7) -- rodent-specific brain extraction workflow
- **nipype** (>=1.7.1) -- workflow engine
- **templateflow** (~=0.7.1) -- template management (Fischer344 atlas)

The package does NOT import from `fmriprep` itself. Instead, it reimplements
or patches the relevant workflows, using shared libraries from the NiPreps
stack (niworkflows, smriprep).

### The patch/ directory -- rodent adaptations

The `fprodents/patch/` directory is the core of what makes this a rodent
pipeline. It overrides upstream components with rodent-specific alternatives:

**`patch/interfaces/__init__.py`**:
- `BIDSDataGrabber`: requires T2w (not T1w); T2w is the primary anatomical
  contrast for rodent imaging
- `TemplateFlowSelect`: fetches T2w template + brain mask (not T1w)
- `RobustMNINormalization`: defaults reference to T2w; special-cases
  Fischer344 template (no resolution variants)

**`patch/workflows/anatomical.py`**:
- `init_anat_preproc_wf()`: complete rodent anatomical pipeline
  - Uses T2w as primary contrast (outputnode fields: t2w_preproc, t2w_mask, etc.)
  - Brain extraction via `nirodents.workflows.brainextraction.init_rodent_brain_extraction_wf`
  - Tissue segmentation via FSL FAST with Fischer344 priors (GM/WM/CSF TPMs
    warped from template space)
  - Spatial normalization via custom `init_anat_norm_wf` with template iterables
  - No FreeSurfer surface reconstruction (not applicable to rodents)
- `init_anat_norm_wf()`: ANTs registration to standard space with
  `poutputnode` (parametric output) + `JoinNode` pattern
- `init_anat_reports_wf()`: QC reportlets using T2w reference images
- `init_anat_derivatives_wf()`: BIDS-Derivatives data sinks

**`patch/workflows/func.py`**:
- `init_bold_reference_wf()`: BOLD reference generation with rodent brain
  extraction (uses `init_rodent_brain_extraction_wf` instead of human-tuned
  skull-stripping)

**`patch/utils/__init__.py`**:
- `fix_multi_source_name()`: generates source names with T2w suffix
- `get_template_specs()`: template resolution handling
- `extract_entities()`: BIDS entity extraction from file lists

### Key rodent-specific differences from fMRIPrep

| Aspect | fMRIPrep (human) | fMRIPrep-rodents |
|---|---|---|
| Primary anatomical contrast | T1w | **T2w** |
| Default template | MNI152NLin2009cAsym | **Fischer344** |
| Brain extraction | ANTs (human priors) | **nirodents** (rodent-tuned) |
| Surface reconstruction | FreeSurfer recon-all | **Not supported** |
| BOLD HMC | FSL MCFLIRT | **AFNI 3dVolreg** |
| BOLD STC | AFNI 3dTshift | AFNI 3dTshift (same) |
| BOLD-to-anat registration | BBR or FLIRT | **FLIRT only** (no BBR) |
| Tissue segmentation priors | Internal | **Fischer344 TPMs from TemplateFlow** |
| CIFTI/surface outputs | Yes | **No** |
| SDC (fieldmap correction) | SDCFlows | **Not yet implemented** (placeholder) |
| N4 bias field correction | Standard settings | **Rodent-tuned** (shrink_factor=1, bspline grid from voxel size) |

### Config singleton pattern

`fprodents/config.py` mirrors fMRIPrep's config singleton. Configuration is
organized into class-based sections that are never instantiated:

- `environment` -- read-only runtime info (versions, CPU, memory)
- `execution` -- run-level settings (paths, BIDS layout, output spaces)
- `workflow` -- pipeline options (ignore, longitudinal, skull_strip_template)
- `nipype` -- Nipype execution settings (nprocs, plugin, memory)
- `seeds` -- PRNG seed tracking
- `loggers` -- centralized logging

Config is serialized to TOML for cross-process communication. The
`init_spaces()` function ensures Fischer344 is always in the output spaces.

Key defaults that differ from fMRIPrep:
- `workflow.skull_strip_template = "Fischer344"`
- `workflow.skull_strip_t1w = "force"` (always run brain extraction)
- Default output space: `Fischer344:res-native`

### Workflow DAG structure

```
init_fmriprep_wf()
  |
  +-- init_single_subject_wf(subject_id)  [per subject]
        |
        +-- BIDSDataGrabber (T2w-first)
        +-- init_anat_preproc_wf()  [patch/workflows/anatomical.py]
        |     +-- init_anat_template_wf() [from smriprep]
        |     +-- init_rodent_brain_extraction_wf() [from nirodents]
        |     +-- init_anat_norm_wf() [custom, with iterables over templates]
        |     +-- FSL FAST segmentation with Fischer344 priors
        |     +-- init_anat_reports_wf()
        |     +-- init_anat_derivatives_wf()
        |
        +-- init_epi_reference_wf() [from niworkflows, with rodent N4 params]
        |
        +-- init_func_preproc_wf(bold_file)  [per BOLD run]
              +-- init_bold_stc_wf() (if SliceTiming present)
              +-- init_bold_hmc_wf() [NOT CONNECTED in current code -- see note]
              +-- init_bold_reg_wf() (FSL FLIRT)
              +-- init_bold_t1_trans_wf()
              +-- init_bold_preproc_trans_wf()
              +-- init_bold_std_trans_wf() (if standard spaces requested)
              +-- init_bold_confs_wf()
              +-- init_carpetplot_wf()
              +-- init_func_derivatives_wf()
              +-- [optional] init_ica_aroma_wf()
```

### Nipype patterns used

1. **Workflow factory functions**: all workflows built by `init_*_wf()` functions
2. **inputnode/outputnode contract**: every workflow has boundary IdentityInterface nodes
3. **Buffer nodes**: `boldbuffer` in BOLD workflow gates STC bypass
4. **Iterables + JoinNode**: template normalization uses `inputnode.iterables`
   on templates, with `JoinNode` for synchronized output collection
5. **KeySelect**: used for selecting Fischer344 transforms for carpet plots
6. **LiterateWorkflow**: `__desc__` attributes generate methods boilerplate
7. **DerivativesDataSink**: all outputs go through BIDS-compliant sinks with
   `out_path_base = "fmriprep"`

fprodents /path/to/bids /path/to/output participant \
    --participant-label 01 \

    --skip-bids-validation \

### Docker build

```bash
# Build the container image
make docker-build                         # tags as nipreps/fmriprep-rodents:latest
make docker-build tag=0.4.0              # custom tag

# Run from container
docker run --rm nipreps/fmriprep-rodents:latest --version
```

The Dockerfile is a multi-stage build:
1. `src` -- builds the Python wheel
2. `downloader` -- base for downloading external tools
3. `freesurfer` -- FreeSurfer 6.0.1
4. `afni` -- AFNI (3dTshift, 3dUnifize, 3dAutomask, 3dvolreg only)
5. `ants` -- ANTs 2.3.3
6. `micromamba` -- conda environment with FSL, C3D, Python deps
7. `fmriprep` -- final image combining all of the above

The container pre-caches the Fischer344 template from TemplateFlow.

## Code style and conventions

### Formatting

- Max line length: 99 characters (flake8 configured in setup.cfg)
- Emacs/vi modelines at top of most files
- `# fmt:off` / `# fmt:on` blocks around `workflow.connect()` calls to
  preserve alignment of connection tuples
- 4-space indentation, no tabs

### Naming conventions

- Workflow factory functions: `init_<name>_wf()` -- always return `pe.Workflow`
- Workflow names use underscores: `"bold_reg_wf"`, `"anat_preproc_wf"`
- Config access: `config.section.field` (e.g., `config.workflow.bold2t1w_dof`)
- Interface patches: prefix with `Robust` or `Fix` + original name

### Commit message style

The project uses conventional-ish prefixes:
- `fix:` -- bug fixes
- `ci:` -- CI/CD changes
- `maint:` -- maintenance and dependency updates
- `REF:` -- refactoring
- `DOCKER:` -- Docker-specific changes
- `docs:` / `doc:` -- documentation only (CI skips builds for these)

Branch naming:
- `master` is the default branch
- Feature/fix branches: `ci/...`, `docker/...`, `maint/...`, `docs/...`

Special commit messages:
- `[skip ci]` -- skip GitHub Actions
- `[skip tests]` or `[skip_tests]` -- skip CircleCI smoke tests
- Commits starting with `docs:` skip Docker builds in CircleCI

## How to add or modify workflows

### Adding a new BOLD processing step

1. Create the workflow factory in `fprodents/workflows/bold/<step>.py`
2. Follow the `init_*_wf()` convention with `inputnode`/`outputnode`
3. Add `__desc__` to the `LiterateWorkflow` for boilerplate generation
4. Wire it into `init_func_preproc_wf()` in `bold/base.py`
5. If config-driven, add fields to `config.workflow` in `config.py` and
   CLI arguments in `cli/parser.py`

### Modifying anatomical preprocessing

The anatomical pipeline lives in `fprodents/patch/workflows/anatomical.py`,
NOT in upstream smriprep. This is a complete replacement that:
- Uses T2w contrast throughout
- Calls nirodents for brain extraction
- Uses Fischer344 priors for tissue segmentation

To modify it, edit `init_anat_preproc_wf()` directly. The output contract
(outputnode fields) must remain compatible with `init_single_subject_wf()`
in `workflows/base.py`.

### Adding a new template

1. Ensure the template is available in TemplateFlow with T2w image + brain mask
2. The `TemplateFlowSelect` interface in `patch/interfaces/__init__.py`
   fetches `suffix="T2w"` and `desc="brain"` mask -- the template must have these
3. `RobustMNINormalization` has a special case for Fischer344 (no resolution);
   new templates may need similar handling if they lack resolution variants
4. Update `config.init_spaces()` if a new default space is needed

## Common pitfalls and things to watch out for

### T2w vs T1w confusion

The entire pipeline is T2w-primary. Many variable names and upstream
interfaces still use `t1w` terminology internally (inherited from smriprep).
For example, `init_anat_template_wf` from smriprep takes `inputnode.t1w`
even though T2w images are being passed in. The outputnode of
`init_anat_preproc_wf` uses `t2w_*` field names, but downstream connections
in `workflows/base.py` map these to `anat_*` inputs on the BOLD workflow.
Watch for this naming mismatch when tracing data flows.

### SDC (susceptibility distortion correction) is not implemented

Despite some fieldmap-related CLI arguments and data files being present,
SDC is NOT functional. The `use_fieldwarp=False` parameter is hardcoded
throughout the BOLD workflows. The `susceptibility_syn.json` and
`fmap-any_registration.json` files exist but are not actively used in the
rodent pipeline.

### HMC workflow connectivity

The BOLD reference is now generated by `init_epi_reference_wf` (from
niworkflows) in `init_single_subject_wf`, which produces both the reference
image and the HMC transform (as LTA). The separate `init_bold_hmc_wf` in
`workflows/bold/hmc.py` (using AFNI 3dVolreg) exists but is NOT currently
connected to the main BOLD workflow. Motion correction comes from the
epi_reference_wf's output `xfm_files`, converted from LTA to ITK format
via `LTAConvert`.

### FreeSurfer: present but vestigial

FreeSurfer is included in the Docker image and the CLI has FS-related
arguments, but surface reconstruction is not performed for rodents. The
license check is still enforced (inherited from the CLI flow). Some FS
paths appear in config but are not actively used by the rodent workflows.

### Template resolution handling

Fischer344 has no resolution variants in TemplateFlow. The
`RobustMNINormalization` interface in `patch/interfaces/__init__.py`
special-cases this by setting `default_resolution = None` when
`template == "Fischer344"`. New templates must be checked for this.

### smriprep import patterns

Several smriprep utilities are imported and used:
- `init_anat_template_wf` for T2w reference generation
- `apply_lut` for BIDS-compliant segmentation labels
- `DerivativesDataSink` and output utilities from `smriprep.workflows.outputs`
- `TemplateDesc` for parsing template specifications

These imports create tight coupling with specific smriprep versions.

### FAST segmentation label order

FSL FAST outputs tissue classes in the order: background(0), WM(1), CSF(2), GM(3).
BIDS requires: background(0), GM(1), WM(2), CSF(3). The pipeline applies a
look-up table remap via `lut_anat_dseg` with mapping `(0, 3, 2, 1)`.
Similarly, `_probseg_fast2bids()` reorders probability maps from
(CSF, WM, GM) to (GM, WM, CSF).

### Reports reference T2w

The reports-spec.yml uses `suffix: T2w` throughout (not T1w). If adding new
reportlets, use T2w suffix consistently for rodent anatomical reports.

## NiPreps-specific conventions

### BIDS compliance

- Input datasets should be BIDS-valid (validation via `bids-validator` in CLI)
- The `.bidsignore` should only contain items truly outside BIDS scope
- Derivatives are written under `<output_dir>/fmriprep/` following
  BIDS-Derivatives conventions
- `dataset_description.json` is generated automatically via
  `write_derivative_description()`

### TemplateFlow

- Fischer344 is the only pre-cached template in the Docker image
- Templates are fetched via `templateflow.api.get()` with specific suffixes
- The patched `TemplateFlowSelect` interface expects `suffix="T2w"` (not T1w)
- `config.init_spaces()` ensures Fischer344 is always present in output spaces

### Provenance

- Every run gets a unique UUID (`config.execution.run_uuid`)
- Config TOML is saved to `<output_dir>/fmriprep/sub-<id>/log/<uuid>/fmriprep.toml`
- Sentry telemetry is opt-out via `--notrack`
- Boilerplate text (methods section) is auto-generated from `__desc__` attributes

### QC checkpoints

1. **Anatomical brain mask**: reported in `anat_reports_wf` (dseg overlay on T2w)
2. **Spatial normalization**: before/after overlay of subject T2w vs template
3. **BOLD-to-T2w registration**: FLIRT reportlet (`desc-coreg`)
4. **Confounds**: carpet plot, CompCor variance, confound correlations
5. **BOLD validation**: NIfTI header validation report
